# 星锋突击 · STARSTRIKE

> **2D 竖版**太空卷轴射击 · 三关卡 · 关底 BOSS · 五级强化 · 双难度
> 引擎：**Three.js 正交 2D + 自研 HDR 后处理管线**，可打包为 Windows / macOS / Linux 独立 APP

## 〇之三、最新一轮调整

| 要求 | 落地方式 |
|---|---|
| **射击声音更改柔和** | 旧版开火音靠「3.4kHz 高通瞬态 + 方波 + FM 金属泛音」堆锐度，单发带劲但连射发"炸"。现在整条链路倒向中低频：软音头改**低通**噪声（1.5k，"呼"而非"咔"）、主体由锯齿+方波换成**三角波 + 半量锯齿**、低通 Q 从 5.2 降到 **2.1**（消掉共振尖峰）、FM 泛音深度砍到约 1/3、尾音带通从 5.2k 压到 2.6k，**链路末尾再挂一个 3.6kHz 总低通**把所有毛刺磨掉。短延迟总线的反馈 0.26→**0.15**、低通 2800→1500 并新增 0.35 湿声增益，避免连射糊成轰鸣。音高抖动也从 ±3% 收到 ±2.3%。激光持续音同步降噪（带通 Q 5.5→3.6、高通嘶声 3600→2200 且音量减半） |
| **第二关陨石可击破** | 陨石从"纯障碍"变成**可打碎的目标**：`ASTEROID` 新增 `hpBase/hpPerSize`（生命值 = 30 + 尺寸 × 42，实测最大 115）、`shootScale`、`respawnDelay`、`score`、`drop`。`game._hitAsteroids()` 用**子弹 + 激光**双通道结算伤害，打空后爆炸 + 碎屑 + 积分 + 概率掉落，陨石隐藏 1.15s 再回到屏幕上沿重生。判定半径刻意分成两个：撞击用 `hitR`（0.42×尺寸），被射击用 **`shootR`（1.15×尺寸）** —— 想打碎它比躲开它更容易命中。命中时陨石会整体提亮闪白，让"在掉血"看得见 |
| **掉落强化道具封顶 5 级** | 5 项武器强化（火力 / 散射 / 导弹 / 僚机 / 激光）各自 `maxLevel: 5`，满级后再吃同类道具不再递增，改为飘字 **「已满级 +200」**并把道具折成积分。护盾 / 核弹 / 生命属于"层数即存量"的消耗品，不受此限。拾取飘字同时改成 `Lv.N/5` 形式，一眼能看到还剩多少空间 |
| **第一关敌机射速 −20%** | 新增**关卡级**射速倍率 `LEVELS[].enemyFireMul`：第 1 关 **1.25**（射速降 20%），第 2/3 关 1.0。它乘在原有的难度倍率与全局保险系数之上，因此第 1 关（教学关）的弹幕明显最舒缓 —— 实测侦察机有效开火间隔 **3.65s**（第 2/3 关为 2.92s） |
| **第二、三关 BOSS 生命 +50%、攻击 +20%** | `BOSS_DEFS` 新增 `hpMul` 与 `atkMul`：VESPER 1.0 / 1.0（保持基准），**CASTOR 与 NOVA 均为 1.5 / 1.2**。血量 = `hp × hpMul × 难度 bossHpMul`（普通难度 40,000 / **84,000** / **114,000**）；攻击倍率同时作用于**弹幕伤害**（`_shot()` 统一出口）与**扫射光束 dps**（`_beamSweep()` 统一出口），阶段分界用血量比例判定因此自动跟随 |

> **顺手修掉的一个验收坑**：封顶之后，"再吃一个激光应该升级"这条断言在满级状态下
> **永远不可能成立**。所以验收脚本必须先 `setLevel("laser", 3)` 把等级降下来 ——
> 而且这一步必须在读取基线**之前**做，否则基线仍停在 5、拾取后只到 4，断言 `4 > 5`
> 会静默等到超时（第一版就是这么误报的）。**任何"上限类"改动都要回头检查验收基线。**

| 要求 | 落地方式 |
|---|---|

| **竖版** | 世界 18 × 32 = **9:16**；外壳按可用高度反算画布宽度（`main.js` 的 `layout()`），HUD 全部尺寸由 `--sw` 自定义属性以 `em` 驱动，随画布等比缩放 |
| **射击音效增强** | 开火音改为**五层合成**（瞬态锐击噪声 + 锯齿/方波双下扫 + 亚低频冲击 + FM 金属泛音 + 尾音嘶嘶），再过一条**短延迟总线**（72ms 延迟 / 0.26 反馈 / 2.8kHz 低通）叠出空间感；每次开火带 ±3% 随机音高偏移，消除"打点机"般的单调感。另加激光三件套（起振/强度/收束）、护盾吸收音、生命拾取音 |
| **敌机射击速度降低一点** | `DIFFICULTIES.enemyFireMul` 语义改为**越大越慢**（普通 1.24 / 精英 0.92），叠加基准间隔整体拉长（侦察机 1.35s → 2.05s），再乘全局保险系数 `ENEMY_FIRE_SAFETY = 1.15`；实测侦察机有效间隔 **2.92s**。同时给所有敌机加了 0.26–0.50s 的**蓄能预警**（开火前先亮一下），弹幕因此变得可读 |
| **射击光效增强** | 这是 2D 化最大的红利：贴图亮度上限为 1.0，**只有刻意 HDR 化的光效**（`material.color > 1`）才会越过 Bloom 阈值。于是阈值可以压到 `1.00`，机体与背景**完全不参与辉光**。子弹=「加性外辉光 + 加性高亮弹芯」双层实例化网格，弹芯亮度 1.85–2.80；枪口带沿炮口方向拉伸的四芒闪光；命中带溅射火花 |
| **加入激光武器** | 全新 `LaserSystem`：**持续光束**，沿长度滚动的周期贴图 + 三重正弦呼吸；每 3 级激光 **+1 道光束**（最多 5 道），叠加同时提升宽度（0.34 → 1.42）与 DPS（30 → 90/道）；命中判定为"竖直线段 vs 圆"，属于独立伤害通道，不消耗子弹池 |
| **护盾、生命掉落** | `POWERUPS` 新增 `shield`（绿 H，12 权重）与 `life`（粉 ♥，3 权重）；另有**保底投放** `GUARANTEED_DROPS`：每关开局送护盾、BOSS 前送修复、BOSS 后送一命 + 火力 + 激光。掉落物**磁吸半径 4.2**、加速度 58，靠近即被吸走，不会"刚好没接住" |

> 其余需求全部保留：三关、关底 BOSS、无限叠加强化、两种难度、独立 APP、画面炫丽。

## 〇之二、本轮平衡调整

| 要求 | 落地方式 |
|---|---|
| **增强敌机生命值** | `ENEMY_TYPES[].hp` 整体上调约 70%：侦察机 20→**34**、截击机 44→**74**、炮艇 155→**260**、轰炸机 265→**440**、炮台 115→**195**、精英机 205→**345**、无人机 16→**26**。图鉴里即为真实基准值，再乘难度倍率 `enemyHpMul` |
| **增强敌机攻击力** | 每型新增 **`dmg` 字段**（单发弹丸伤害），在 `_shoot()` 里传给 `BulletField`：侦察 12 / 截击 13 / 炮艇 15 / 轰炸 17 / 炮台 14 / 精英 16。同时撞机伤害 `ramDamage` 普通 22→**32**、精英 30→**44**。**顺带修掉一个隐患**：原 `game.js` 用 `n = round(ehit / 10)` 反推命中数，隐含假设了"所有敌弹都是 10 点伤"——一旦给敌弹分型就会算错，现在直接采用 `hitCircle()` 返回的累计伤害 |
| **删除空间中不会变化的物体** | 这不是美术问题，而是**一个真 bug**：`EnemyManager.clear()` 只写 `list.length = 0`、没有把网格从 scene 上摘掉，于是从菜单切进游戏时，菜单里那批装饰性敌机就变成**永远冻结在画面上的孤儿网格**（实测残留 12 架，不移动、不参与碰撞、永不消失，也回不了对象池）。改为倒序调用 `_retire()`，网格与对象池一并回收 |
| **陨石撞击消耗生命值** | 第 2 关的岩屑带从纯装饰改为**可碰撞实体**：`config.ASTEROID` 集中管理数量 / 尺寸范围 / 碰撞半径系数 / 伤害公式；`world.shatterRock()` 让被撞碎的陨石回到上方重生（场上数量恒定，无需额外池）。撞击走 `_playerHit()`，因此**护盾可以抵挡、无敌帧依然生效**；伤害随陨石体积递增（`12 + 尺寸 × 7`，实测 25 点） |
| **缩短每关卡时间 20 秒** | `LEVEL_DURATION` 180→**160**（2:40），`BOSS_AT` 138→**118** —— BOSS 登场同步前移，**BOSS 战窗口仍是 42 秒**。`levels.js` 的阶段分界（28/56/88/114 → 24/48/75/98）与特殊事件时刻（94/66/60/130 → 80/56/51/111）按 118/138 的同一比例重排，各阶段节奏比重与旧版完全一致；`main.js` 里硬编码的跳关时刻 `139` 也改为引用 `BOSS_AT` |

> **这一轮最值钱的一条**：用户报的"画面里有几架不会变化的战机"听起来像美术需求，
> 实际是**对象生命周期 bug**。定位方式是抛弃猜测、直接量化——写一个探针比对
> "场景里的敌人网格数"与"逻辑敌机数"（`groupChildren: 24` vs `listLen: 0` → 24 个孤儿），
> 再用系统级截图肉眼复核，一次锁定。
>
> **教训：任何 `clear()` / `reset()` 只要清空了逻辑容器却没归还 GPU 资源，
> 就是在制造幽灵对象。这类 bug 不会报错、不会掉帧，只会静静地留在画面上。**

## 一、引擎选型说明

| 方案 | 为何选 / 不选 |
|---|---|
| **Three.js 正交 2D + WebGL2（本项目采用）** | 2D 弹幕射击真正的瓶颈不是"建模"，而是**海量发光元素 + 可控辉光**。正交相机让世界坐标与屏幕像素一一对应，碰撞判定与布局全部可以用世界单位直算；`InstancedMesh` 让数百发弹幕只花 2 次绘制调用。同一套代码可打包成桌面 APP（Electron）、移动 APP（Capacitor）与网页版，包体小、可离线。 |
| Unity / Unreal | 对"三关 + 关底 BOSS"这种体量属于严重过重：编辑器依赖、包体 100MB+、无法在纯代码流程里交付可运行产物。 |
| Godot 4 | 轻量、开源，2D 也很好；但仍需引擎编辑器才能迭代关卡，且 HDR 辉光链路不如手写管线可控。 |
| Cocos Creator | 2D 完善，但自研 HDR 管线与实例化弹幕的可控性低于裸 WebGL2。 |

**结论**：本项目用 Three.js 手写了完整的渲染管线（亮部提取 → 5 级降采样高斯 → 加性上采样 → 色散/Bloom/ACES/暗角/颗粒/扫描线/超空间扭曲/受击闪白/低血红边 → sRGB），
不依赖 three/examples 的 EffectComposer，以换取可控的光晕半径与稳定性能。

## 二、2D 化的三个关键设计

1. **无光照管线**
   所有物体 = `PlaneGeometry + MeshBasicMaterial`。全部贴图由 canvas 程序化生成、统一为「白/灰阶 + alpha」，
   颜色交给 `material.color` 着色。这带来一个额外好处：**可以精确指定哪些像素进入 Bloom**。

2. **HDR 光效分级**
   2D 贴图亮度 ≤ 1.0，`postfx.params.threshold = 1.00`。只有刻意把 `material.color` 写到 > 1 的元素
   （子弹弹芯、激光芯/外晕、爆炸火球、枪口闪光、判定点）才过线。机体、敌机、背景亮度全部 ≤ 1.0，
   因此**永远不会**参与辉光 —— 这是「射击光效增强」但画面不发灰的根本原因。

3. **光效用"亮度"而不是"面积"来表现**
   初版把光束外晕、发射点闪光、枪口闪光统统放大，结果满配时自机上方糊成一根白色光柱，机体与弹道全看不见。
   最终方案是：**收紧几何尺寸，保留高亮度** ——
   光束外晕 `×1.55`（原 2.35）、发射点软光 `×1.20`（原 2.90 四芒星）、枪口沿竖直方向拉伸
   （横向拉伸会变成两块"白色机翼"）、炮口间距从 `0.30` 放宽到 `0.40`
   （5 路弹道不再互相叠加）。**层次感来自核心亮 / 外晕柔 / 有间隙，而不是全部拉满。**

## 六、运行与打包

```bash
npm install            # 安装 esbuild / electron / electron-packager

# 1) 开发：本地服务器（推荐 Chrome / Edge / Firefox）
npm run dev            # → http://127.0.0.1:5173

# 2) 生成图标（PNG + 多尺寸 ICO）
npm run icon           # → assets/icon.ico, assets/icon-256.png …

# 3) 构建单文件（可离线、可双击运行）
npm run build          # → dist/starstrike.html （约 634 KB，含 Three.js）

# 4) 桌面独立 APP
npm run dist:win       # → dist-app/StarStrike-win32-x64/StarStrike.exe
npm run dist:mac       # → dist-app/StarStrike-darwin-arm64/StarStrike.app
npm run dist:linux
npm run app            # 不打包，直接以 Electron 启动调试
```

> **首次打包提示**：`electron-packager` 需要下载 Electron 运行时。
> 国内网络若失败，设置镜像后重试：
> ```bash
> export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
> node node_modules/electron/install.js
> ```

> **打包原理**：`scripts/package.mjs` 会先把运行期真正需要的文件（游戏单文件包 +
> `electron/main.js` + 图标 + 精简 `package.json`）暂存到 `build/stage/`，
> 再对暂存目录打包并启用 `--asar`。因此产物里不含 `src/`、`tools/`、`node_modules/`，
> 既干净又不会泄露源码。

> **两个 Windows 打包坑（脚本已内置兜底，若换环境仍可能遇到）**：
> 1. `electron-packager --overwrite` 内部走系统回收站，可能抛
>    `Error during a trash operation` —— 即使文件没被占用。脚本改为打包前先用 `fs.rmSync` 自己清。
> 2. 某些安全加固环境会**劫持 Node 的 `fs.rm*` / PowerShell 的 `Remove-Item`**，把删除重定向到回收站，
>    回收站不可用时连 `rmSync` 也会失败；若上一次产物里的 `app.asar` 又被系统句柄锁住，
>    该目录既删不掉也改不了名。此时脚本会**自动换用 `dist-app-r2`、`-r3`…** 作为输出根目录，
>    保证打包永远能出结果，并在日志里标注实际路径。

## 七、自动化验收（浏览器内实测）

项目自带一个**零依赖**的 Chrome DevTools Protocol 验收脚本（Node 22 内置 `fetch` + `WebSocket`，
不需要 Puppeteer / Playwright），会把游戏真跑一遍并逐步截图：

菜单 → 出击 → 实战 6s → 满配（各强化封顶 Lv.5）+ **封顶不可突破验证** →
**射击音效合成链路自检**（清节流后连打 30 发 + 敌机开火 + 激光开关）→ 激光特写 →
**掉落验证（护盾 / 生命 / 激光 三件，轮询等待被磁吸拾取）** → 读取敌机开火参数 →
跳 BOSS → 三阶段推进 → **停火观察 BOSS 弹幕** → 击破 → 第 2 关 → **陨石可击破验证** →
第 2 关 BOSS（血量核对）→ 第 3 关（精英）→ 第 3 关 BOSS → 通关结算 → 回菜单 → 10s 稳定性巡检。

```bash
# 1) 起一个允许远程调试的 Chromium 内核浏览器（无 Chrome 时用 Edge，CDP 协议一致）
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --remote-debugging-port=9222 \
  --user-data-dir=./.browser-profile --enable-unsafe-swiftshader about:blank

# 2) 起静态服务器（必须常驻，别放在会随 shell 退出的子进程里）
python -m http.server 8123

# 3) 跑验收（源码版本）
node tools/cdp-verify.mjs --url http://127.0.0.1:8123/ --port 9222 --out .verify

# 4) 跑验收（单文件构建产物，验证 file:// 下不会被 CORS 拦住）
node tools/cdp-verify.mjs --url "file:///绝对路径/dist/starstrike.html" --port 9222 --out .verify-dist

# 5) 验收打包后的桌面 APP
node tools/app-check.mjs --exe dist-app/StarStrike-win32-x64/StarStrike.exe --out .verify-app

# 6) 快速诊断（只看 console / 异常 / 关键 DOM 状态 + 一张截图）
node tools/quick-check.mjs --url http://127.0.0.1:8123/ --wait 4000
```

> **写这类脚本时的三个坑（本项目都踩过）**：
> 1. **`fetch('http://127.0.0.1:...')` 可能被代理环境变量拦掉**。Node 在 Windows 上不认 `NO_PROXY`，
>    若 `HTTP_PROXY` 指向本地代理，连 127.0.0.1 都会被代理走 → `fetch failed`。
> 2. **不要在同一个 Bash 调用里启动浏览器再连它**。要用 `run_in_background` 常驻启动、等它起来再连。
> 3. **掉落的道具不是"瞬间拾取"**。它要从上方落下、进入磁吸半径后才被吸走。用固定 `sleep` 去断言
>    会误判成"掉落未生效"——必须**轮询等待状态变化**（本项目初版就因此误报了 2 个 feature 失败）。
> 4. **必须 `Network.setCacheDisabled({ cacheDisabled: true })`**。复用同一个 `.browser-profile` 时，
>    浏览器会从磁盘缓存加载旧模块，于是你改的代码根本没跑起来。这个坑特别有迷惑性：
>    现象是"新加的函数报 not a function"，但"新改的数值却已经生效"（因为不是所有文件都命中了缓存）。
>    本项目本轮就因此白跑了一轮验证。
> 5. **改架构时要同步验收工具链**。`app-check.mjs` 是 2.5D 时代写的，引用了
>    `g.director.t` / `g.camDist` / `g.boss.invulnerable` / `g.boss.pods` 等已删除的 API，
>    2D 化后一直没跑过，直到本轮才暴露。**验收脚本也是代码，会腐烂。**
> 6. **改"上限"必须回头改验收基线**。给强化封顶 Lv.5 后，「再吃一个激光应该升级」在满级下
>    恒不成立；且降级动作必须发生在**读取基线之前**，否则基线停在 5、拾取后只到 4，
>    断言 `4 > 5` 会静默等到超时。
> 7. **抽"在场的活物"做单元验证前先复位状态**。随手从第 2 关取一颗陨石，它往往已被打残，
>    一发就碎、血量被重置成上限 → "扣血"读数会变成负数。

## 十、性能说明

* 弹幕全部走 `InstancedMesh`，**绘制调用与弹幕数量无关**（自机弹 / 敌弹各 2 次）
* 粒子为单次绘制的点精灵层（火花 / 辉光 / 烟 / 拉丝四层），着色器支持逐粒子尺寸/颜色/透明度
* 对象池覆盖敌机、子弹、道具、冲击波、爆闪、粒子，运行期零分配
* 星空使用固定像素尺寸（`sizeAttenuation: false`），分辨率变化时视觉大小一致
* 粒子尺寸以「世界单位」给出，由 `uScale` 换算为设备像素，因此改分辨率不会改变观感
* 检测到帧率持续低于 46 FPS 时自动降档（降低 MSAA、Bloom 分辨率、像素比）；
  恢复到 58 FPS 以上且处于最低档时回升一级
* 渲染缓冲高度上限 1700px，避免 4K 屏把 Bloom 链撑爆
* `postfx.render()` 在 `renderScene` 之后、`present()` 之前采样 `renderer.info`，
  否则统计到的永远是后处理最后一趟单 quad 的 `drawCalls = 1`

## 十一、已知取舍

* **美术全部程序化**（canvas 路径 + 逐像素 `ImageData`），因此没有外部美术资源、
  包体极小、可离线；代价是细节丰富度不及手绘位图。
* **2D 化放弃了实时光照**。优点是彻底可控的 Bloom 分级与更高的性能余量；
  代价是机体没有金属反射与高光，靠贴图上的渐变与发光条来表现体积。
* **`legacy-3d/`** 保留了上一版 2.5D 的全部源码作为存档，不参与构建。
* **移动端**给出了 Capacitor 方案但未实测；触摸操作与虚拟按钮已实现。
